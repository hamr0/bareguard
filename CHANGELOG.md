## [0.14.0] — 2026-08-31

### Fixed

- **Every per-field bound in the audit truncation block was taken in UTF-16 code units, not bytes — in a block whose entire purpose is a byte budget.** The guards read `Buffer.byteLength(v, "utf8") > 200` but cut with `String.prototype.slice(0, 200)`, which counts code units: a 200-unit slice of CJK is 600 bytes and of astral emoji 400. Measured before the fix — a `reason` of 5000 CJK characters persisted at **611 bytes** against the 211-byte bound the code and the entries above both claim (2.9x), astral emoji at 411 (1.9x). `result` was worse in kind, not just degree: its guard read `.length > 200`, a code-unit **count**, so a 200-character CJK value (600 bytes) was **never truncated at all**. Six sites were affected — the `action` per-key string, the `result` per-key string, `where`, `verdict`, `reason`, and the last-resort scalar keep at 120. Honest scope: **no line could be constructed that breached `MAX_LINE_BYTES`**, because the wholesale-collapse stage re-bounds the line regardless of the first pass's imprecision and `reason` never co-occurs with `where`/`verdict`/`meta` on the same line (every `emit()` call site checked). So this was a false *field-level* guarantee, not a live atomicity breach — but it silently ate the margin that the next forgotten field will need, and this exact enumeration has now failed four times (`verdict` in 0.13.0, `reason`, the key-count bypass, and this). All six now route through one `clipBytes(s, max)` helper that cuts on a UTF-8 `Buffer` and drops the single U+FFFD a split multi-byte sequence decodes to, so the bound is exact rather than approximate; the same helper replaced the hand-rolled byte-safe slice the `action.type` fix had introduced separately, so there is one implementation and not two. It slices to `max` code units before copying, so a hostile 150 KB value costs 0.040 ms/call rather than 0.201 (measured, both). 5 regression tests — CJK and astral `reason`, a multi-byte `result` value, `where`/`verdict` driven over the line cap by compounding redaction, and an under/at/over probe of the 200-byte boundary itself to pin that a byte-exact cut does not start truncating values that were always legal. Four of the five are mutation-verified red against the code-unit slice; the boundary test is ASCII and stays green by design, since it guards over-truncation rather than the byte bug. Found by `/diff-review` on the assembled branch — the `action.type` fix had already applied this lesson in one place while five older sites carried the flaw forward untouched.

- **`action.type` did not survive the payload collapse, so the cold-start budget rebuild reclassified the round.** The line bound above replaces `action`/`result` wholesale with `{_truncated, bytes}` when per-field truncation is not enough — which drops `action.type`. `_rebuildBudgetFromAudit` classifies a historical round with `l.action.type !== "llm"`, so a collapsed llm round read as `undefined !== "llm"` and was rebuilt as a **tool** round: measured live `toolRounds: 0` vs cold-start `toolRounds: 1` for identical input (a 200-key `{type:"llm", ...}` action, persisted at 319 bytes). That is precisely the live-vs-rebuilt divergence 0.9.0 closed *by construction* by routing both paths through `sanitizeSpend`, reopened on the `toolRounds` dimension by the backstop that fixed the line cap. The error direction is **over**-count, never under — a collapsed line always increments, so it halts early rather than permitting overspend — but the two paths must not disagree, and "by construction" must not have an exception. `type` is now carried through the collapse. It is caller-controlled, so it is re-bound by **bytes** (`Buffer.byteLength` + a byte-wise slice), not UTF-16 code units, inside a branch whose entire purpose is a byte budget — a character slice of 120 astral code points would cost up to 480 bytes. Found by `/code-review medium` on the line-bound commit and confirmed by execution before the fix; 2 regression tests (the divergence itself, which fails pre-fix with `undefined !== 'llm'`, and a multi-byte `type` that would defeat a character-based slice), both re-run green with the whole suite at 290.

- **The audit line's atomicity guarantee was enforced per FIELD, not per LINE, so many small keys blew the cap while the line still claimed `_truncated: true`.** `action` and `result` were truncated by iterating their keys and capping each *value* at 200 bytes — nothing bounded the key *count*. Measured: an action of 200 keys × 190 bytes passed every per-key check and persisted as a **40,197-byte** line against the 3500-byte `MAX_LINE_BYTES`, an order of magnitude over POSIX `PIPE_BUF` (4096), which is the threshold the whole mechanism exists to stay under; the same shape on `result` produced 40,173 bytes. `meta` was never vulnerable because it collapses the *whole object* once its total exceeds 200 — that is the shape the guarantee actually needs. The promise is about the line, so it is now enforced on the line: after per-field truncation the serialized length is re-checked, and if it is still over, `action`/`result` collapse wholesale to `{_truncated, bytes}` (preserving the real size and leaving `reason`/`rule`/correlation intact), with a final backstop that keeps every scalar field and drops object payloads. **This bug predates the branch and is reachable on `main`** — the per-key loop is unchanged by the `reason` fix. What this branch got wrong was the *claim*: the in-code comment it added ("Re-bound every field … to keep the line atomic on POSIX FS") and its INVARIANT note both asserted a guarantee that did not hold, because enumerating fields is not the same as bounding the line. That enumeration has now failed three times — `verdict` in 0.13.0, `reason` in this branch, and the key-count bypass here — which is why the check is aggregate rather than another field added to a list. Honest limit: the final scalar-only backstop is **not reachable by any input that could be constructed**, so no test kills that branch; it is kept as an unconditional guarantee-by-construction and labelled as an uncovered branch rather than claimed as tested.

- **A caller-supplied config key reached an exception message unbounded and unredacted.** `assertArrayShapedConfig` interpolates the offending tool name into the `Error` it throws for `tools.denyArgPatterns.<tool>`. A thrown `Error` is not routed through the audit redactor and nothing downstream caps it, so a key built programmatically from an upstream tool registry could carry arbitrary data into whatever logs construction failures. Measured: a 2,000,000-character key produced a 2,000,077-character message. Keys are now clipped to 64 characters in the message; a normal key is still named in full so the error stays actionable. Introduced by this branch, not pre-existing.

- **Array-shaped config keys were never validated, and a non-array produced four different silent wrongs — including a fail-open on the shipped safe defaults.** Measured before the fix: `content.denyPatterns: {}` (or `42`/`true`/a `Set`) **replaced** the safe-default deny floor with something matching nothing, so `rm -rf /` went from `deny` to **`allow`**; `fs.deny: "/etc"` iterated the string per CHARACTER, so the resulting entry `"/"` matched every absolute path and the gate denied **everything**, silently bricking it; `tools.denylist`, `net.allowDomains`, `fs.readScope` and `bash.allow` **threw** `globs.some is not a function` out of the gate mid-action, and `tools.denyArgPatterns.<tool>` threw `patterns is not iterable` — a different mechanism (`for...of` over the value, not `matchAny`), which the first version of this entry misattributed; and `tools.allowlist` denied at runtime (fixed separately, above). None of these were reported to the operator. Config is operator-authored and read once at construction, so it is now validated there and throws — matching `budget`, which already throws on an invalid resource cap or `softRatio`. `tools.denyArgPatterns` is the one config surface that is a **map of arrays** rather than an array, so the flat `[section, key]` model could not express it and its per-tool values were initially left unguarded — the natural authoring slip (`{ bash: /rm -rf/ }`, one pattern with the wrapper forgotten) still threw out of `check()`. It is now validated as a map, each value required to be an array, and guarded at runtime by rule `tools.denyArgPatterns.invalid` so an unevaluatable deny rule fails CLOSED rather than vanishing. Thirteen flat keys are covered: `tools.allowlist`/`denylist`, `content.denyPatterns`/`askPatterns`, `fs.deny`/`readScope`/`writeScope`, `net.allowDomains`, `bash.allow`/`denyPatterns`, `secrets.keys`/`patterns`/`envVars`. `undefined`/`null` still mean "not configured" and are skipped; `[]` is a legal array (an empty scope, and the documented `content` pure-allow opt-out) and still constructs. The per-action `tools.allowlist.invalid` deny is **kept** rather than superseded: `Gate` holds `this.cfg = config` **by reference** (verified by mutating a config after construction and observing the deny still fire), so the constructor check alone would not cover a caller that swaps a value out later — the two layers guard different moments. Validated by POC before any code changed: the validator was measured against 8 known-bad and 6 known-legal shapes (8/8 caught, 0 false positives) before being wired in. Four mutations verified — and the third initially stayed GREEN, exposing that the first version of the test used only *truthy* non-arrays, so a truthiness-based skip would have waved `""`/`0`/`false`/`NaN` through; the test now pins the falsy cases explicitly.

- **The audit line's atomic-append cap was not enforced on `reason`, so a caller-controlled value could blow it while the line still claimed `_truncated: true`.** `reason` is redacted like `action`/`result`/`where`/`verdict`/`meta`, but the oversize-truncation fallback in `audit.js` re-bounded all of those and not `reason` — the same omission, in the same block, that let an 80-char `verdict` reach 63,669 bytes before 0.13.0. `reason` is worse in one respect: `where` and `meta` are capped at the source by `gate.annotate`, whereas `reason` has no upstream bound at all, so it is both unbounded AND expanded by redaction. Every rule that echoes caller data into it is affected — `tools.allowlist.exclusive` and `tools.denylist` (`action.type`), `fs.deny`/`readScope`/`writeScope` (`path`), `net.invalidUrl`/`denyPrivateIps`/`allowDomains` (`url`/`host`), `flags.<field>` (the field value), and the `humanChannel threw` path (`err.message`). Measured over the 3500-byte cap: 7432 bytes for `tools.allowlist.exclusive`, 7507 for `fs.deny`, 7463 for `net.invalidUrl`, and **4510 bytes at DEFAULT configuration with no `secrets` config whatsoever** — a long `action.type` alone is enough, because redaction only amplifies a field that was already unbounded — rising to **60,408 bytes** once three broad patterns compound over each other's `[REDACTED:…]` markers. All of these were persisted with `_truncated: true`, a false promise of boundedness, and all exceed POSIX `PIPE_BUF` (4096), which is the actual threshold below which an `O_APPEND` write is guaranteed atomic; a concurrent writer could interleave into the middle of one. Now re-bounded to 200 bytes plus a `[TRUNCATED]` marker exactly like `where` and `verdict`: the worst case above drops from 60,408 to 704 bytes, and a short reason is still persisted verbatim. **This bug predates the empty-allowlist change and is reachable on `main`** (verified in a clean worktree: `tools.denylist` produces 7394 bytes there, on a code path this branch never touches); the empty-allowlist fix only widened one trigger, because `tools.allowlist: []` now reaches `action.type` where it previously returned early. The block comment claimed it truncated "all large action fields and result strings" while excluding two fields it also had to cover, so it now states the invariant instead: any field added to the redactor must also be re-bounded here. 4 regression tests, one per amplification path plus an over-truncation control; mutation verified — deleting the re-bound turns 3 of them red.

### Changed

- **A present-but-unusable `tools.allowlist` now denies instead of falling through or throwing.** The empty-allowlist fix guarded on `!cfg.allowlist`, which closed `[]` but left JS falsiness swallowing four more *present* values: `""`, `0`, `false` and `NaN` all read as "scope not configured" and fell through to default **allow** — so a config-templating bug (an unset env var joined into a string, a falsy default from a config loader) failed OPEN in exactly the way the `[]` fix exists to prevent. A truthy non-array (`"search"`, `{}`, a `Set`) was worse still: it reached `matchAny` and threw `globs.some is not a function` out of the gate. Now only `undefined`/`null` leave scope unconfigured; every other non-array value denies with the new rule **`tools.allowlist.invalid`**, matching the house pattern already used by `fs.invalidPath`, `net.invalidUrl` and `bash.invalidCmd` — present-but-wrong-type is denied, not waved through. Validated by POC before any primitive was touched: the first two candidate guards (`=== undefined || === null`, and an `Array.isArray`-spelled variant) were measured across the full input matrix and **both failed** — they fixed the falsy cases but left the truthy non-array still throwing, so the guard needed the explicit array check rather than a cleverer falsiness test. The accepted shape changes no currently-correct outcome: absent and `null` still mean unconfigured, `[]` still denies via `tools.allowlist.exclusive`, `["*"]` and a real match still allow. Three mutations verified red — reverting to the truthiness guard, dropping the non-array arm, and re-opening the `[]` hole. Note a hostile *config* object (an `allowlist` getter or Proxy trap that throws on read) still throws; config is operator-authored and trusted at construct time, unlike an action, so that is out of scope by design.

- **BREAKING: an empty `tools.allowlist` now fails CLOSED.** `tools.allowlist: []` was folded into "not configured" — step 5 was skipped and the action fell through to default **allow**, so the *tightest expressible scope produced the loosest possible outcome*, silently and with no rule attributed. Only an **absent** `allowlist` key now means "scope not configured"; `[]` is a configured scope of nothing and denies every action with the existing rule `tools.allowlist.exclusive`. The guard changed from `if (!cfg.allowlist || cfg.allowlist.length === 0)` to `if (!cfg.allowlist)`; no new rule id, no new config key, no new audit phase. Every sibling scope primitive — `net.allowDomains`, `fs.readScope`/`writeScope`, `bash.allow` — already denied on `[]` (measured, not assumed); `tools` was the sole outlier, and the inconsistency is what made the cookbook's tighten-only resolver carry a hand-written `length === 0` guard as its documented headline foot-gun. The concrete failure this closes: a capability bundle whose intersection with the floor is empty (two misspelled tool names is enough) resolved to `[]` and therefore permitted `wireMoney` — a typo turned the narrowest bundle into allow-all. Rejected alternatives: throw-on-construct (a deny is structured in-band agent feedback, a throw is not) and keep-and-lock (a fail-open is expensive to carry past 1.0 and cheap to fix at 0.x). **Migration:** if you passed `[]` expecting allow-all, delete the key. 3 regression tests; two mutations verified to break the suite — reverting the guard, and flipping `matchAny()`'s empty-globs return, the downstream re-bound point that actually renders the deny. Resolves the `bareguard-prd.md` last-call breaking-change review item.

  Swept the rest of the config surface for the same class — the tightest expressible value being silently read as "key not configured" — and found no second instance of it; the sweep is pinned as `test/tightest-value-invariant.test.js` rather than left as a one-off finding, so a future scope-shaped key cannot reintroduce the class quietly. The surface sorts into five families, not the three the first pass named. Allow-scopes (`tools.allowlist`, `net.allowDomains`, `fs.readScope`/`writeScope`, `bash.allow`) deny on `[]`. Deny-lists (`tools.denylist`/`denyArgPatterns`, `fs.deny`) treat `[]` as identical to absent, which is correct: for a negative list the empty set genuinely is the loosest value, so there is nothing to conflate. Numeric caps (`budget.maxCostUsd`/`maxTokens`/`resources`, `limits.maxToolRounds`/`maxTurns`) all read via `?? Infinity`, so a cap of `0` stays a real cap — this is the same bug in numeric form (`|| Infinity` would read `0` as "no cap") and it is absent by construction. **`content` is its own fourth family and the one key where `[]` and absent deliberately disagree**: `contentDenyCheck`/`contentAskCheck` read `cfg.denyPatterns ?? SAFE_DEFAULT_DENY_PATTERNS`, and `??` keeps an empty array, so `content.denyPatterns: []` *replaces* the shipped safe-default deny floor instead of being ignored — `[]` is strictly **looser** than absent there. That is the documented pure-allow override (PRD §11) and is deliberate, not a fail-open: the operator wrote "no patterns" and gets exactly that, loudly, rather than the tools bug's silent inversion. It now has its own test asserting the difference, rather than being filed under deny-lists as if `[]` and absent agreed. A fifth family is additive-extend: `secrets.keys`/`patterns`/`envVars` and `classify.extra*` are spread onto their shipped defaults (`[...base, ...(cfg.keys ?? [])]`), so `[]` extends by nothing and a default cannot be disabled by writing an empty collection — opting out is a separate explicit flag (`secrets.redactKeys: false`). Verified by running it rather than by reading: `makeRedactor({keys: []})` still blanks a live `apiKey`, and `classifyCommand("rm -rf /", {extraDestructive: []})` still returns `super_destructive`. This matters most for `secrets`, where content-style replace semantics would put live credentials into the audit log. Monotonicity is pinned directly: walking `tools.allowlist` down a subset chain to `[]`, the permitted set only ever shrinks. Mutations verified red, one per family, including flipping `?? Infinity` to `|| Infinity`.

### Added

- **Publish workflow gates on the types being usable BY AN ADOPTER, not just internally.** `npm run typecheck` (`tsc --noEmit`) checks the *source*; it cannot see the generated `.d.ts` as an adopter resolves it from inside `node_modules`, which is the one thing consumers actually get. The publish workflow now packs the tarball, installs it into a clean consumer project, and compiles a quickstart against it, so a release whose published types are broken cannot reach the registry.  The consumer pins `@types/node` to the major this package builds against instead of floating to the newest, so a stricter DefinitelyTyped release cannot turn the publish gate red for reasons unrelated to the commit being published. Verified locally: the quickstart compiles green against a packed tarball, and a deliberately broken dereference fails it. CI only — no runtime or published-artifact change.

### Fixed

- **Adopter type-check gate no longer runs dependency install scripts next to the publish credential.** The gate installs the packed tarball into a throwaway consumer project, and that install ran inside the job holding `id-token: write` — the OIDC credential that can publish this package — with install scripts enabled, so any install script in the tarball's transitive dependency tree executed beside a live publish capability. Now `--ignore-scripts`. The gate only ever runs `tsc`, which reads `.d.ts` and nothing else, so nothing needs building: verified on a native-addon package that the addon is *not* compiled and the type check still passes green, while a broken dereference still fails it. `typescript` is also pinned to `@5` for the same reason `@types/node` is pinned — an unpinned compiler silently becomes a new major and fails the gate on its own schedule rather than on the commit's merits. CI only — no runtime or published-artifact change.

## [0.13.0] — 2026-08-13

### Changed

- **`gate.annotate` now REJECTS a malformed fact instead of normalizing it into a silently-honored one (Axis-B fail-open).** `surface` must be an **explicit boolean**. Before this, three separate doorways — `annotate([fact])` (an array; `typeof [] === "object"`, so the non-object guard never caught it), `annotate({kind, field, stated, returned, text})` (the retired pre-E6 sketch shape, which a downstream doc cited as current), and `annotate({verdict, where})` (a shipped-shape call that simply forgot `surface`) — all normalized to `{surface:false, verdict:null, where:null, meta:null}`. That value is **byte-identical to a legitimate `honored` fact**, so it routed as `pass` and no human ever saw it: "I could not read what you sent" and "everything was fine" were the same value. The rule is one line because `surface` is the only load-bearing and only non-optional field, so setting it is what separates a caller speaking the contract from one speaking a different dialect; it closes all three doorways plus `{}` and a truthy `"false"` string. On malformed: **nothing is buffered** (the drain is authoritative for downstream consumers and must stay clean), **no decision changes**, and a **distinct `annotate_malformed` audit row** records `reason` (`"not-an-object"` | `"array"` | `"missing-surface"` | `"unreadable"`) — a record, not a verdict, in the same loud-signal-no-decision class as `unpriced` and `budget_warn`. A distinct *phase* rather than a flag on `annotate`, because a flag would still let a parser counting `phase === "annotate"` miscount a rejection as a fact. **Behavior + audit-format change** (both 1.0-surface items; additive on the audit side, and the cheapest possible moment pre-1.0). An explicit `surface: false` is unaffected — honored facts buffer exactly as before. Verified at the source against the only shipped consumer, `bare-agent@0.36.0`: `judgeToAnnotation()` returns a single object literal computing `surface: v.verdict !== 'honored'`, i.e. always an explicit boolean, so the rule costs it nothing. 10 tests, each mutation-verified (four mutations, incl. the tempting half-fix, each confirmed to break the suite).
- **Agent/IDE scratch is gitignored and de-tracked (`.claude/`, `.litectx/`, `.idea/`).** Per-machine agent and IDE state is no part of the package — it regenerates locally and only added noise and churn. Now ignored, and any already-committed copies removed from tracking (local files kept on disk). Functional dot-paths (`.github/`, `.gitignore`, `.npmignore`, `.mcp.json`) stay tracked. Repo hygiene only.


### Fixed

- **`gate.annotate()` no longer throws into the agent loop when the fact explodes on READ (pre-existing).** `surface`, `verdict`, `where` and `meta` are all caller-controlled property reads, so any of them can be a getter or Proxy trap that throws — and it did, straight out of `annotate()` and into the caller's loop, breaking the one contract Axis B leans on (a detector must never break the loop it observes). Measured against the pre-change code too: this predates the malformed-rejection rule above; it is not a regression from it. Every read of the caller's object — the shape check **and** the normalization — now sits inside the guard, and a throw becomes a fourth malformed reason, `"unreadable"`, handled exactly like the other three (nothing buffered, loud audit row, no decision changed). An unreadable fact is rejected **whole** even when `surface` itself read fine: half-read is not "everything was fine", which is the same conflation the rejection rule exists to kill. **The never-throws guarantee is now stated precisely rather than absolutely** — it covers *the fact*, not the disk: an audit **write** failure (`ENOSPC`, unwritable path) still propagates, deliberately, because a silently-dropped audit line is the worse failure and every other phase behaves the same way. Both halves are pinned by test, so the guarantee cannot quietly widen back. The docs previously asserted the unqualified version while the code did not hold it. Each caller field is now also read into a local **exactly once**, so the value validated is the value stored by construction: `verdict`/`where` were type-tested and then re-read to slice them, which a getter answering differently on the second read could exploit to slip a non-string past the type check.

- **A secret in an annotation's `verdict` was written to the audit file RAW (pre-existing).** The 0.7.0 Axis-B hardening added audit-time redaction for `where` and `meta` — the reply-derived annotation fields — but missed `verdict`, which is equally caller-judge free text. Measured with a `secrets` pattern configured: `where` persisted as `leaked [REDACTED:pattern=sk-A...]` while `verdict` persisted as `broke: sk-ABCDEFGHIJKLMNOP` verbatim, into the shared audit file the whole "no raw secrets on disk" guarantee covers. `line.verdict` now goes through the same redactor. Regression test asserts the raw key is absent and the marker present, and that `where` is unchanged.
- **`meta`'s 1000-byte bound was undoable after the fact (pre-existing).** `boundMeta()` returned the *caller's own object* when it fit under the cap, so a judge that kept appending evidence to the object it had already handed to `annotate()` grew the drained fact and the `humanChannel` event past the documented cap — **after** the bound had run. Worse, the two sinks then disagreed: the audit row is serialized at emit time, so it kept the small version while the drain carried the grown one (measured: **17-byte audit row vs 5031-byte drained meta** for the same fact). Under-cap `meta` is now carried as a decoupled copy (a round-trip through the JSON already computed for the size check — no extra cost), so the bound is a fact rather than a request and both sinks agree. The caller keeps their own object and may mutate it freely. This matters now because the same change set promotes that cap to a documented, citable contract in the shipped typedef.
- **A `__proto__` key in an annotation's `meta` could shift a consumer's prototype (pre-existing).** `meta` is reply-derived — the least trusted data the gate carries — and a hostile reply parsed with `JSON.parse` yields `__proto__` as an ordinary own property. Inert while it sits on the fact, but a consumer merging the fact (`Object.assign({}, fact.meta)`, a spread) turns that key back into a real prototype set on the merged object. The key is now dropped while copying, **at every depth**, the same treatment `safeAction()` has given actions since 0.6.0. Global `Object.prototype` was never polluted, before or after. Related and fixed by the same copy: `meta` built as an object literal with a real `__proto__` (an actual prototype, not a key) no longer carries that prototype into the fact either.
- **Publish workflow pinned to `npm@11` — npm 12.0.0's `npm publish --provenance` is broken.** The job ran `npm install -g npm@latest`, which started resolving to npm 12.0.0 (released 2026-07-09) on the Node 22 runner. npm 12's `libnpmpublish` provenance code does `require('sigstore')`, but the tarball bundles only the `@sigstore/*` scoped packages — so `--provenance` dies with `MODULE_NOT_FOUND` and the publish fails outright. npm@11 bundles `sigstore` and publishes fine. Pinned to the major rather than floating on `@latest`. Revisit once npm ships a provenance fix. CI only — no runtime or published-artifact change.

### Docs
- **pico-type fit assessment — the secrets-seam premise is REFUTED by measurement, not deferred on taste** (`docs/01-product/pico-type-fit-assessment.md`). Evaluated `eulogik/pico-type` (byte-level NN content classifier, 7 heads incl. a risk/secrets head) as a candidate `secrets` / file-type detector. A falsifiable POC — real ONNX weights, freshly-generated real-format secrets as positives, benign near-misses as negatives — measured **risk-head recall 0.46 on embedded secrets**, against the author's same-generator synthetic AP=1.0. Root cause is structural: it is a **whole-blob classifier, not a span detector**, so a key inside an `.env` line, a code comment, or past the 1024-byte window goes silent — which is exactly the gate's input shape. A 5-line regex catches what it misses, so it does **not** beat the deterministic pattern floor, and compose-as-recall-aid is dead too (its misses are a superset of the easy regex cases). Coarse file-type routing scored 5/10 on real files; latency ~38 ms/call (not the 5.5 ms README headline, which is `batch_size=64` amortized). **Verdict: SEED/NOT-NOW** — no `src/` change, no adopter ask. The only surviving use is zero-code bareagent type-routing via MCP (nice-to-have).

## [0.12.0] — 2026-07-07

### Added
- **BG-3 — `INTERPRETER_PATTERNS`, an opt-in tier-2 escalation for inline-interpreter code (multis ask, 2026-07-07).** New frozen export: canonical regexes for `python -c`, `node -e`, `perl -e`/`-E`, `ruby -e`, `node`/`deno --eval`, `php -r`. **Not** in any default set — inline interpreter code (`python3 -c "shutil.rmtree('/')"`) stays `safe` by default and *cannot* be reliably gated (the identical action via `python3 script.py`, a heredoc, or `base64 | sh` is invisible to any regex), so a default escalation would be a false-positive flip for every consumer that buys almost no safety. Instead the boundary is now **explicit** in `classify.js` (this is the module's honest-scope limit, made discoverable at the call site rather than silent), and a consumer that wants a coarse HITL speed-bump opts in: `classifyCommand(cmd, { extraDestructive: INTERPRETER_PATTERNS })`. bareguard owns the canonical pattern shape (Principle 8); the array is `Object.freeze`d — read-only introspection, never a mutable module-global. Type: `readonly RegExp[]`.

### Changed
- **BG-1 — `rm -rf` of a whole system root or home account is now `super_destructive` (multis ask, 2026-07-07).** The tier-3 `rm` patterns matched only `/`, `~`, and a bare `$HOME`; `rm -rf /etc`, `/usr`, `/boot`, `/home/alice`, `/Users/bob`, `"$HOME"`, `${HOME}` all classified merely `destructive` even though each is as irrecoverable as `rm -rf /`. ## [0.10.0] — 2026-06-29

### Added
- **BG-1 — key-aware secret redaction in the audit, DEFAULT-ON (F16; relayfact upstream ask; pairs with bareagent BA-1).** The `secrets` redactor previously matched only **values** (`envVars` from `process.env`, `patterns` RegExp) and ran **only when `secrets` was configured** — so an adopter who never set `secrets` and threaded a live provider into `_ctx` wrote `action._ctx.provider.apiKey` (the full `sk-ant-…`) verbatim to the audit JSONL (relayfact F16, probe-03). ### Security
- **Greedy default `Bearer` pattern would leak the secret it was meant to redact — caught and fixed by the BG-1 test before any release.** The first-cut default value-pattern `Bearer\s+\S+` is greedy over the **serialized JSON** the redactor operates on: `\S+` swallows the closing `"` and `}`, corrupting the line so `JSON.parse` fails and `redact()` **bails to the un-redacted original** — the raw key lands on disk. Same class as the 0.8.0 `bash.classify` ReDoS (a default pattern that's unsafe against the data shape it runs on). Fixed to a charset-bounded `Bearer\s+[A-Za-z0-9._\-+/=]+` that stops at the JSON string terminator. Verified: the redactor is ReDoS-linear (50k-char / 2000×-repeat adversarial inputs ≤ 1 ms), builds redacted nodes with `Object.create(null)` so an own `__proto__` input key can't pollute `Object.prototype`, is non-mutating (eval sees the real action), and the default-on expansion is re-bounded by the existing unconditional `MAX_LINE_BYTES` truncation net (a file-backed near-boundary line stays ≤ 3500 B, valid JSON, `_truncated:true`) — so PIPE_BUF audit-line atomicity holds.

Adds `resources`/`softRatio` to `BudgetConfig` and `counts` to `Result` in `types.js`.
- **Joinable audit lines — a per-action correlation id (harness-prd OQ4, a2a §12.2).** Each `check()` eval mints a short `aid` stamped on every audit line it emits and returned on the decision; `record(action, result, { aid })` stamps the same id on the record line, and `run()` threads it automatically — so a request joins to its outcome (and its approval) in one record **even when two actions are byte-identical** (which content-join cannot disambiguate). The compose seam (separate `check`→`record`) joins by reading `decision.aid`; omit it and `record()` mints its own (today's behavior — no regression). Adds optional `aid` to the `Decision` typedef.
- **Axis B return-time judge — `gate.annotate` (harness-prd §8.2, the first Axis-B `src/` surface).** A thin, opt-in primitive: the caller hands the gate a return-time-judge **fact** `{ surface, verdict?, where?, meta? }` (did a returned value *honor* the user's request?); bareguard **buffers** it, **audits** it (`phase:"annotate"`), lets it **ride the next human ask** `check()` raises (the human sees independent facts, not the agent's spin), and exposes it for **agent feedback** via `gate.drainAnnotations()`. bareguard **never runs an LLM and never decides an outcome** — the fact is the caller's, the judge (if any) is caller-side. Routing is the pure exported `routeAnnotation(surface, reversible, knob)` (`surface × reversibility × knob`): **reversibility is read from the GATED ACTION's type** via the operator's `axisB.reversible` list — never the fact, the agent, or the model (a hallucinated "reversible" must not auto-pass a booking); the `axisB.reversibleEscalation` knob (`strict` default | `relaxed`) is pure noise control on the reversible path, never safety. **B never blocks alone** — worst case it annotates an ask Axis A already raised; **with no `annotate()` call the decision path is byte-identical**. Adds `Annotation` / `AxisBConfig` typedefs, `axisB` to `GateConfig`, and `annotations` to `HumanEvent`.

### Security
- **`gate.annotate` audit lines redact secrets and bound their fields (Medium, fixed in the same change — surfaced by the `/security` pass on the Axis-B build).** Two hardenings on the new return-time-judge sink: (1) the audit redactor now also covers the annotate line's reply-derived `where` / `meta` (it previously only touched `action` / `result` / `reason`), so a secret echoed by a judge into `where` is no longer persisted raw when `secrets` is configured — preserving the gate's "audit never carries raw secrets without the caller pre-redacting" guarantee; redaction stays audit-only (the live `humanChannel` event and `drainAnnotations()` keep the real value). - **Generic resource counts are monotonic and bounded (Low, fixed in the same change).** `result.counts` accrues only **positive** deltas for **configured** resources: a negative delta is rejected (counts can't be un-spent — closes a "refund" evasion of the cumulative cap) and unconfigured keys don't accrue (bounds the shared budget file against arbitrary count keys; observed-only counts still appear on the record line via `result`). ## [0.5.2] — 2026-05-29

Turns on `strictNullChecks` over the sources — closing the null-safety gap behind the v0.5 types — and simplifies the typecheck setup. Also fixes a Windows-only flake in the v0.5.1 atomic budget write. No public-API change.

### Fixed

- **`defer` / `spawn` rate limiting now enforces in fileless audit mode (was fail-open).** The rate-window counter is fed by the gate's rate context, which carries the in-memory `entries` array (not a file path) when `audit.path` is `null`. `deferRateCheck` / `spawnRateCheck` only forwarded `auditPath`, so in fileless mode the trailing-window count was always `0` and the per-minute cap **silently never fired** — a fail-open in a policy primitive (it previously threw on the null path, which a hardening guard in this release had quieted to a `0`). Both checks now also forward `entries`, so the cap is counted from the in-memory log; file mode is unchanged (`entries` is `null` there and the file is read as before). Fileless mode is documented test-only, but a security control should never silently no-op. Regression tests added for both primitives.
- **Atomic budget write no longer flakes on Windows (`EPERM` on `rename`).** v0.5.1 made `Budget._write()` write to a temp file then `rename` it over the target — atomic on POSIX, but on Windows `rename`-replace (`MoveFileEx`) intermittently throws `EPERM`/`EACCES`/`EBUSY` when the destination is momentarily held by another process (Defender, the search indexer, a lagging handle close), even with the write serialized under the budget lock. That error propagated out of `record()` and crashed the worker — which is what failed the `windows-latest / Node 22` CI leg (a worker exited non-zero in `audit-stitching`). The rename now retries on those transient codes with a short backoff (~550ms worst case, well under the 20s lock `stale`); the retry is win32-only, so the POSIX path and the happy path are unchanged. Same strategy as `write-file-atomic`/`fs-extra`.

### Changed

- **`strictNullChecks` is now enabled on the source typecheck (`tsconfig.json`), and the ~45 findings it surfaced are fixed.** The v0.5.0 type work checked a strict *consumer fixture* but ran the source itself with no null-checking, so genuine null hazards in the `.js` were invisible. The fixes are behaviour-preserving narrowing: `gate.check()` now derives its decision as `this._haltCheck() ?? await this._stepEval(action)` (was a nullable `let` that TypeScript couldn't prove non-null); `Audit` and `Budget` capture the nullable `filePath` / `sharedFile` into locals past their fileless/local-mode guards so the narrowing survives `await` and closure boundaries; and the rate-window helper takes `string | null` / `object[] | null` and returns `0` for "no audit source" instead of throwing a `TypeError`. Full `strict` stays off (the hand-written JS still trips ~130 unrelated strict errors that don't affect the emitted declarations); `strictNullChecks` is the slice that matters for null safety and for the generated `.d.ts`.
- **Typecheck simplified to a single `tsc` project.** The strict consumer-resolution fixture (`tsconfig.consumer.json` + `test/types/consumer.ts`) is removed: it ran full-strict against a stub while missing every real null issue in the actual source, so `strictNullChecks` on the source is both simpler and strictly more thorough. `npm run typecheck` is now just `tsc -p tsconfig.json`.
- **`prepare` → `prepublishOnly` for the `.d.ts` build.** Declarations are still generated into `types/` and shipped via the `files` allowlist; they're now built before publish rather than on every `npm install`. npm consumers are unaffected (the tarball carries pre-built `types/`); a git/`file:` dependency would need `npm run build:types` to populate them.

## [0.5.1] — 2026-05-29

### Fixed

- **Shared budget file is now written atomically (temp file + `rename`).** `Budget._write()` used `fs.writeFile`, which opens the target with `O_TRUNC` and then writes — exposing a zero-length window. Under concurrent multi-process load a reader could hit that window and `JSON.parse` an empty string, throwing `BudgetUnavailableError: …Unexpected end of JSON input` (the v0.4.7 "fail loud on corrupt read" path misclassifying a transient truncation as corruption). This surfaced as an intermittently-flaky `shared-budget` test. ## [0.5.0] — 2026-05-29

Ships TypeScript types for the library, plus policy-bypass hardening from a security audit. Minor bump for the new public capability (typed consumption).

### Security

- **Type-confusion fail-open closed in `fs` / `net` / `bash` (H1).** A present-but-non-string `path` / `url` / `cmd` (an array, a `{ toString }` object, a number) previously made the primitive return "no opinion" — the action then fell through to the allowlist and was **allowed**, bypassing `deny` / `writeScope` / `readScope` / `denyPrivateIps` / `allowDomains`, while the executor coerced the value back to a real string (`{ toString: () => "/etc/passwd" }`). The `bash` allow path additionally threw a `TypeError` mid-eval. These now **deny** with `fs.invalidPath` / `net.invalidUrl` / `bash.invalidCmd`. An absent field is still a no-op.
- **Backslash traversal no longer escapes `fs` scope on Windows (M2).** `norm()` used `path.posix.normalize`, which treats `\` as an ordinary character — so `/scope/..\..\etc` left its `..` segments uncollapsed and escaped the scope on win32 (a CI-supported platform). Backslashes are now folded to `/` before normalization.
- **Glob `*` now matches line terminators (L1).** `globToRegex` compiled without the `s` flag, so `.` didn't match `\n` / `\r` — a tool name like `"danger\nous"` slipped past a `tools.denylist` glob (`"danger*"`). The compiled RegExp now uses dotAll. The allowlist direction was already fail-closed and is unaffected.

### Documented (intentional limitations surfaced by the audit)

- **`net.denyPrivateIps` matches the literal host only — it does not resolve DNS (M1),** so a hostname whose record points at a private/metadata address is not caught. It's defense-in-depth, not an SSRF boundary; `allowDomains` (fail-closed) is the control to bound egress. Numeric-encoding vectors (decimal/octal/hex/short-form/mapped-IPv6) are **not** a bypass — the WHATWG URL parser normalizes them before the check. Now noted in the README, the `net` JSDoc, and `NetConfig`.
- **`secrets.envVars` skips values shorter than 8 characters (L2)** to avoid masking incidental short strings (port numbers); use a `patterns` entry for short secrets. Now noted in `SecretsConfig` and the source.

### Not changed

- **`defer`/`spawn` rate window scans the full audit log per check (validated, left as-is).** It's O(n) per check (O(n²) over a long run) on the hot path. An early-stop optimization was implemented and then **reverted**: the audit log is only approximately time-ordered across processes, so any position-based early-stop can under-count in-window records — and for a rate limiter an under-count is a cap **bypass**. A full timestamp scan is the only provably-correct option; bound the cost by keeping runs / audit files reasonably sized. (Equivalence testing under reordered timestamps is what caught the regression.)

### Added

- **Ships with TypeScript types.** The public API is now fully documented with JSDoc, and `.d.ts` declarations are generated from it (`tsc --emitDeclarationOnly --allowJs`) so TypeScript consumers — and JS editors — get full IntelliSense and compile-time checking on the `Gate` config, the decision/event shapes, and every re-exported primitive. JSDoc is the single source of truth; the declarations are generated (into `types/`) by the `prepare` script and shipped in the package, never hand-maintained. Named config types are importable from the root (`import { Gate, type GateConfig } from "bareguard"`) or from the `bareguard/types` subpath. No runtime change — bareguard remains plain ESM JS. A `typecheck` CI job (`tsc`) plus a strict consumer-resolution fixture (`test/types/consumer.ts`) guard the JSDoc and the published types against drift.

### Docs

- **README quick-start no longer pre-redacts before `check()`.** It showed `gate.check(gate.redact(action))`, but since v0.4.5 the gate auto-redacts at the audit boundary when `secrets` is configured, and pre-redacting before `check()` can weaken policy matching (eval should see the real action). Now `gate.check(action)`, matching the Integration Guide. Also refreshed the stale test count (88 → 107) and LOC (~930 → ~1,000).

## [0.4.7] — 2026-05-24

Hardens shared-budget cross-process locking — follow-up to the flaky-test investigation in 0.4.6, validated by a second `/code-review` pass (which empirically tested crash modes and corrected the first cut).

### Changed

- **`budget.record()` now fails loud on an unreadable/corrupt shared budget file.** Previously, if the under-lock read or `JSON.parse` failed, it silently fell back to `spentUsd += dUsd` (stale local state) and wrote that over the committed total — losing spend and risking overspend. It now throws `BudgetUnavailableError` instead, matching the documented PRD §13 contract ("surface `BudgetUnavailableError` and terminate cleanly"). **Migration:** a corrupt budget file that was previously swallowed now propagates out of `gate.record()` / `gate.run()`; wrap those if you want to degrade rather than halt. Normal operation is unaffected — the throw only fires on genuine corruption (a missing file is still re-seeded before the lock, and `init()` keeps its rebuild-from-audit recovery).
- **`proper-lockfile` `stale` raised 10s → 20s** for the budget file. The critical section is sub-millisecond, so a lock steal (which would put two writers in the section and silently lose an update) requires the holder to be frozen that long; 20s shrinks the window while the unchanged ~2.25s retry budget stays well under it (so a process waiting on a live holder always errors before it would steal). Fail-safe tradeoff: a holder hard-killed (SIGKILL) mid-lock makes `record()` throw `BudgetUnavailableError` until the lock ages past `stale` — halting rather than overspending.

### Tests

- **Suite 106 → 107.** New case: `record()` on a corrupt budget file throws `BudgetUnavailableError` and leaves the file untouched (no stale-local clobber). Also folds in 0.4.6's flaky-test fix: `shared-budget.test.js`'s concurrent-spend assertion now checks scheduling-independent invariants (never over-counts; spend accumulates) instead of penny-exact `$0.60`, which contradicted the documented soft-budget contract and flaked CI under lock contention.

## [0.4.6] — 2026-05-23

Fixes from a `/code-review` pass over the 0.4.4/0.4.5 security changes — it caught a fail-open in the `fs` primitive those releases were meant to harden. Suite 100 → 106.

### Security

- **`fs` deny/scope entries written with a trailing slash no longer mishandle the directory node itself.** `path.posix.normalize` keeps one trailing slash, and `within()` only stripped it on the prefix arm — so `deny: ["/etc/secret/"]` did **not** deny `read /etc/secret` (fail-open on the node itself; children were still denied), and `writeScope: ["/app/data/"]` wrongly denied a write to `/app/data` (fail-closed). `within()` now strips a trailing slash from the normalized base before both the exact-match and prefix checks, and special-cases root (`/`).

- **`net.denyPrivateIps` — defense-in-depth for two deprecated IPv6 forms.** IPv4-compatible IPv6 (`::a.b.c.d`, e.g. `[::127.0.0.1]`) is now decoded and classified like the IPv4-mapped form, and the IPv6 local range is widened to cover deprecated site-local `fec0::/10` (`fe8`–`fef`). ## [0.4.5] — 2026-05-23

Security hardening pass — the follow-up to 0.4.4's audit. Three of the remaining findings fixed (the fourth, `allows()`/askHuman, is documented rather than changed since it's correct for its pre-filter purpose). Suite 93 → 100.

### Security

- **`bash.allow` now fails closed on shell metacharacters.** A prefix allowlist can't bound what runs after a chain/pipe/substitution — `bash.allow: ["git "]` previously permitted `git x; rm -rf ~`. These are the "didn't read the spec, hit the foot-gun" issues.

## [0.1.0] — 2026-04-29

First release. Action-side runtime policy library for autonomous agents — bounds what the agent does, not what it says.

### Added

- **Single `Gate` class with three call sites** — `gate.redact(action)`, `await gate.check(action)`, `await gate.record(action, result)`. One chokepoint between the agent and the world; tools never self-check. Plus `gate.run(action, executor)` for runners that want check + execute + record in one call, and `await gate.allows(action)` as a pure boolean catalog pre-filter (no audit, no budget delta).
- **Twelve primitives, ten in v0.1** — `bash`, `budget`, `fs`, `net`, `limits`, `approval`, `tools`, `secrets`, `audit`, `content`. Each ~30–180 LOC in its own file. `defer-rate` and `spawn-rate` ship in v0.2 alongside bareagent's `defer` and `spawn` tools that exercise them.
- **Severity-graded decisions** — every `gate.check` returns `{ outcome, severity, rule, reason }`. `severity: "action"` denies bubble to the LLM as structured errors; `severity: "halt"` events (budget exhaustion, maxTurns, terminate) escalate to a human and never bubble. Run-level safety baked in.
- **`humanChannel` callback** — one runner-supplied function consolidates ALL human escalations (ask + halt + topup + terminate). bareguard calls it; applies the human's decision atomically (audit line, optional cap raise, optional terminate); returns terminal allow/deny to the runner. The runner branches on two outcomes only — never sees `askHuman`.
- **Single audit file across the agent family** — POSIX `O_APPEND` atomicity (< PIPE_BUF / 4KB) means parent + children + grandchildren all `appendFile` the same `$XDG_STATE_HOME/bareguard/<root-run-id>.jsonl` without locks. Family tree reconstructable from one file with grep on `parent_run_id`. Phases: `gate`, `record`, `approval`, `halt`, `topup`, `terminate`. Windows uses a lock fallback automatically.
- **Shared budget across processes** — `budget.sharedFile` + `proper-lockfile` (the one allowed production dep). Versioned format (`version: 1`). Parent + children draw from one cap. On a missing/corrupt budget file, bareguard rebuilds spent + cap from the audit log on startup.
- **Safe defaults shipped** — `content.denyPatterns` blocks `DROP TABLE`, `rm -rf /`, `TRUNCATE TABLE`, force flags. `content.askPatterns` escalates `delete`, `revoke`, `truncate`, `force-push`, destructive HTTP methods. ~10 lines of regex covering ~90% of dangerous things agents do. Override with empty arrays for pure-allow.
- **Six-step eval order, fully pinned** — pre-eval halt checks (`budget`, `maxTurns`, terminated), then `tools.denylist → content.denyPatterns → per-action-type rules → content.askPatterns → tools.allowlist scope → default allow`. First match wins. Allowlist is **scope-only** — does NOT silence asks (a v0.5 reversal of the v0.4 short-circuit which proved a foot-gun in practice).
- **Secrets redaction with name tagging** — `[REDACTED:ANTHROPIC_API_KEY]` for env-var matches, `[REDACTED:pattern=sk-...]` for unknown-source pattern matches. Never shows full secrets, never shows the suffix. Caller is responsible for redacting tool results before `gate.record`.
- **Multi-agent stitching** — `parent_run_id` and `spawn_depth` threaded via env vars (`BAREGUARD_PARENT_RUN_ID`, `BAREGUARD_SPAWN_DEPTH`, `BAREGUARD_AUDIT_PATH`, `BAREGUARD_BUDGET_FILE`). Children inherit automatically.
- **`gate.haltContext()`** — deterministic stats over the audit log (spend, turns, last-5 spend rate, time elapsed). Exposed for `humanChannel` to render to operators. No LLM speculation on remaining work.
- **Glob `*` only** — minimal wildcard for tool name matching. No `?`, `[abc]`, or escapes in v0.1. v0.2 may add `**` if real use exposes pain.

### Tests

- 30/30 tests passing on Linux. ~700 LOC of tests covering eval order, safe defaults, secrets redaction, halt flow (humanChannel + topup + terminate + audit dedicated halt line + budget reconstruction from audit), shared-budget under real-subprocess contention, single-audit-file atomicity across 3 concurrent processes, and a full agent-loop integration.
- **GitHub Actions matrix CI** — `ubuntu-latest`, `macos-latest`, `windows-latest` × Node 20 / Node 22. Six combinations on every push and PR.

### Constraints

- **One production dep:** `proper-lockfile` (for the shared budget file). Hard target per PRD §18.
- **Source ≤ 1000 LOC:** 931 LOC in `src/`. Per PRD §21 success criterion.
- **Complete mediation:** every action goes through one `gate.check`. No bypass paths. No tool self-checks.

### Philosophy (carried from PRD §17)

bareguard is **action-side** — bounds what the agent does. Not content (use `guardrails-ai`). Not sandboxing (use Docker/gVisor). Not authn (caller's concern). Not a scheduler. Not a daemon. No telemetry, no SaaS. The goal is to be small enough to read in an afternoon and understand exactly what your agent is allowed to do.

### Known limitations

- **Soft cap.** Cross-process budget can be exceeded by one action's spend before next refresh. Halt fires reliably on the next check after a record.
- **Safe-default `askPatterns` over-match.** `/\b(delete|drop|...)/i` fires on innocent strings. Right v1 trade — over-asking is recoverable; under-asking is incidents. Narrow patterns if noisy.
- **Linux/macOS primary.** Windows works via lock fallback but isn't CI-verified yet.
- **No rate limits in v0.1.** `defer-rate` / `spawn-rate` ship in v0.2 with bareagent's `defer` / `spawn` tools.

### bareagent migration note

bareagent v(next) will remove its built-in `bash` allowlist, token/cost budget, per-tool gov layer, max-turns counter, and ad-hoc tool-call logging — all replaced by `import { Gate } from "bareguard"` and one policy adapter on `Loop({ policy })`. See `bareguard.context.md` Recipe 8 (or the bareagent-side recipe in its own context doc when published).
